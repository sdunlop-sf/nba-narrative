02Triggers

Four ways to start a decision, one engine behind them

⚡

Real-time segment

A Data 360 segment activates when a customer qualifies, and the objective it's attached to is decided.

◷

Scheduled

Daily or hourly runs decide ahead for whole segments, so every customer has a current next best action.

{}

Decision API

Any system asks for a decision for one customer, with the reasons and ranked alternatives if requested.

◎

Flow & agents

A Flow, the console or an agent invokes arbitration directly, for example after a call.

03The rails

Rules that hold in every mode. Reasoning can't talk its way past them.

RailWhat it doesWho sets it
Global suppressionOpted out, vulnerable, hardship, regulatory, deceased or legal hold: blocked before anything is ranked. The unbreakable floor.Compliance
Channel policyContact caps per channel over 7 days, cooldowns, and fatigue that builds with contact and decays over time.Channel owners
Cooldown across objectivesStops two teams contacting the same customer too close together. Only critical actions can bypass it, with a recorded reason.Decisioning owner
EligibilityPer-action include and exclude segments, and start and end dates.Offer owners
Budget & stockOffer budgets and inventory; an action drops out when its limit is reached.Offer owners
Score thresholdA minimum score; below it, the right answer may be to do nothing.Decisioning owner

Restraint is a first-class outcome. When every action fails a rail, the engine records a "do nothing" decision with the reason, which is a signal in its own right.

04Headless by design

Any app, channel or agent can ask for a decision

API

Decision REST API

Request a decision for a customer or for one objective, record outcomes, read customer context, run simulations.

Platform

Flow & invocable actions

The same arbitration exposed as actions for Flow and Agentforce, so a service agent can ask "what should I offer?" and get the reasons.

Developers

Agent tools

A tool server lets developer agents query, explain and simulate decisions. It's deployed alongside the package, not inside it.

05What ships

What's in the package, and what you configure

In the package

Installs in one step

  • Action catalogue and objectives
  • Content catalogue and content selection (from your CMS)
  • Offer resolution with Real-Time Offer Management (promotions, treatments, rotation)
  • Arbitration engine with tiered reasoning
  • Contact policy, suppression and cooldowns
  • Decision record with a full reasoning trace, sealed against edits
  • Holdouts, lift measurement and learned weights
  • Admin app: simulation, review queue, operations
  • Decision REST API and invocable actions
  • Channel senders for Flow, webhooks and Slack; a service console component

You configure

Set up in your org

  • Data 360 streams, segments and activations
  • Your shelf: actions, offers and promotions, and content from your CMS (Contentful, AEM or Salesforce CMS)
  • Policies and priorities
  • A connection to your consent source
  • Marketing Cloud journeys that deliver the decisions
  • Scheduled jobs after each install or upgrade
  • Optional: AI re-rank and composition, Agentforce agent, developer tool server

06Getting started

From install to a measured first decision, in weeks

Step 1

Install and connect

Install the package and connect Data 360: streams, segments and a dispatch activation.

Step 2

Load the catalogue

Actions, offers, priorities, contact policy and suppression. Existing recommendations can be migrated.

Step 3

Dry-run

Run one objective in dry-run alongside production. Read the decision traces; nothing is sent.

Step 4

Go live with a holdout

Switch the objective to live with a holdout from day one, so lift is measured, not assumed.
